This is a distinct E7 executable feature, built on the existing E6 research branch. It is not another E3.9G, E4, E5, or Runtime #23 checkpoint.

Functional implementation: tools/enterprise/e7_agents/e7_offline_cli.mjs starts in PLAN_ONLY_NO_FILES_OR_AGENTS_ACCESSED mode, touching no files, models, workers, or cloud services. With the explicit local operator opt-in AETHERIS_E7_OFFLINE_DELEGATION_OPT_IN=yes and --run-local, it reads exactly three allowlisted regular UTF-8 files (index.html, scene.js, styles.css) in a requested absolute local workspace, rejects symlinks and extra files, and enforces a total 65 KB input budget.

It launches two REAL separate OS processes (one attempt each, no retries, eight-second worker deadline, limited request/response size), without shell commands or arbitrary tools. The integrity specialist computes file digests and sizes. The safety specialist checks local references, main landmark, keyboard skip link, reduced-motion CSS, common event-handler and remote-resource patterns. The coordinator verifies exact worker schemas, independently compares file digests, and produces a deterministic 4-event SHA-256 hash chain with a review candidate/denial decision. The review never modifies input files. Static checks do NOT certify accessibility, JS safety, image rights, aesthetic quality, production security, or real browser behavior. The workers are deterministic programs, not independent LLM agents, and separate Node processes are NOT OS sandboxes or authenticated identities.

Offline export of the review TRACE ONLY is separately gated: an operator must supply a pinned Ed25519 approval public key and its exact SHA-256 fingerprint, and a detached receipt binding action EXPORT_E7_REVIEW_TRACE_ONLY, request UUID, reviewed input digest, trace root digest, absolute output path, issuance, ten-minute validity, and nonce. The signature is independently verified before a single exclusive/non-overwriting 0600 POSIX file write. Wrong key, stale, modified, mismatched-path or already-existing output denies. The key fingerprint is configured locally, NOT pinned by the real Aetheris Identity platform. An attacker controlling this same OS account can configure a different local key and evade the local demonstration policy. Thus even a valid signature sets ownerAuthenticated:false and ownerApproved:false. There is NO owner signature claim and NO production privilege grant, account access, source patch, deployment, model request, signed workload transport, or real tenant task access.

Operator example, after preparing a three-file local site:
- Default: node tools/enterprise/e7_agents/e7_offline_cli.mjs
- Linux/macOS opt-in: export AETHERIS_E7_OFFLINE_DELEGATION_OPT_IN=yes
- Review: node tools/enterprise/e7_agents/e7_offline_cli.mjs --run-local --workspace /absolute/review/site --request-id 984f254a-b4a7-4c4e-84ba-34056d28bb76
- Windows PowerShell: set $env:AETHERIS_E7_OFFLINE_DELEGATION_OPT_IN = 'yes'; use an absolute Windows path.
Signed export additionally needs --export, --approval and --approver-key plus AETHERIS_E7_TRUSTED_APPROVER_PUBLIC_KEY_SHA256. No signer, auto-approval command or private owner key is stored or generated by the product; CI generates ephemeral test keys only.
