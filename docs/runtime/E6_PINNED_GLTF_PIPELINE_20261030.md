## New working content

- `tools/enterprise/e6_studio/generate_reference_gltf.py` reproducibly generates one **glTF 2.0 JSON** research mesh, with its one 864-byte position/normal triangle buffer embedded as a `data:application/octet-stream;base64,` URI. The asset contains **36 triangle vertices**, two float32 VEC3 accessors, a 24-byte interleaved vertex stride, a single buffer view, one mesh, one node and one scene. No images, textures, external file references, Draco extensions, animations, material downloads or external scripts. It is **original, human-authored fixture geometry**, not an arbitrary untrusted glTF importer, a Blender-generated mesh, a product asset, or a model-produced design.
- Its exact canonical bytes are fixed, reproducible and independently SHA-256-pinned to `ace770e960909c2b788312dfd80e9d788ed89fd1eeb3f8008842b4e246af45a7`. The Python validator requires exact supported schema and canonical reference content, numeric bounds and embedded-data length. The generator **refuses overwriting any pre-existing file or symlink**; generated output is local-only and stored with 0600 permissions. The glTF file is generated by a deliberate command, not committed as a binary.
- `gltf_lab/asset_page.html` and `gltf_lab/gltf_scene.js` are a **new isolated second research page**. They reuse the same responsive source-authorized E6 stylesheet and original three-camera arrival/material/precision research choreography, but the WebGL2 buffer now comes from an **actual fetched locally served glTF asset**, not a JavaScript-constructed cube. Before drawing, the browser checks exact pinned SHA-256, glTF 2.0 identity, declared original asset provenance, one local embedded binary, exact accessors/stride/vertex counts and bounded finite float32 values. A file hash mismatch or unsupported/hostile asset triggers **`asset-invalid` static fallback**, without rendering untrusted mesh bytes. The original `reference/studio.js`, index, CSS and browser tests remain untouched.
- The browser loader fetches **only `./reference_mesh.gltf`** from the local host, with no credentials, caching or redirects. It does not install or invoke Three.js/Blender/GSAP, remote asset URLs, external images, model inference, network tools or customer APIs. The resulting geometry uses the existing on-demand GLSL camera transforms and scroll events. The page must be accessed from a **loopback HTTP server** due to browsers' `file://` fetch rules.
- `test_gltf_asset_policy.py` validates pinned deterministic data, input tamper/remote textures/extensions denial, no-overwrite local generator, browser source pin/zero external code and exact demo asset paths.
- `gltf_browser_proof.mjs` starts a short-lived HTTP server bound to `127.0.0.1`, serves this **owned local research fixture**, blocks any browser request outside that origin and executes **actual Chromium software-WebGL2** across desktop/mobile scroll with three camera shots and reverse, real pixel image changes, cap on framebuffer pixels, frozen idle frames, WebGL context loss/static fallback and reload.
