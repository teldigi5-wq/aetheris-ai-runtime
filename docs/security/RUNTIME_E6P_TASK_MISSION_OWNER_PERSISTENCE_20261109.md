## Executable changes

1. [E6P disposable schema/migration rehearsal](../../orchestrator-service/src/test/resources/security/e6p_real_shape_owner_migration_pg16.sql) creates only a fresh CI database's `public.aetheris_tasks` and `public.aetheris_mission_sessions` using the actual JPA-derived table names and relevant columns. **Pre-upgrade historical Task and Mission rows are seeded before migration.** Nullable UID/tenant/project/verification timestamp and workload-fence columns are added to **both** table shapes without backfilling any owner. Check constraints require all five ownership fields or none. An immutable-update trigger rejects owner reassignment, including attempted retroactive claims on old ownerless rows. This is a schema-*shape* rehearsal, not an approved migration on the real production tables.
2. `e6p_review.create_owned` is a narrowly granted SQL `SECURITY DEFINER` function. It checks exact cryptographically verified Identity issuer/kid/JTI/UID/iat through existing Platform E6J session authority; also checks live tenant/project membership and a tenant/project-specific operator-bound workload fence. Both the session checker and the membership/fence checker lock their authority rows in the **same READ COMMITTED transaction as the new Task or Mission INSERT**. No existing Task or Mission can be bound or reassigned through this function. Raw INSERT/SELECT/UPDATE table permissions are never granted to the test writer or reader.
3. A separate `e6o_review.e6p_locked_membership` SECURITY DEFINER helper, owned by the **preexisting E6O authority-table owner**, locks membership, binding and fence records. The first integration attempt failed because the restricted Task writer tried `FOR SHARE` on membership tables without PostgreSQL's required row-lock privileges. The fix did **not** grant writer UPDATE rights. Instead, it preserved separate authority ownership and scoped function EXECUTE. Teardown ordering was corrected so no cross-role ACLs remain in the disposable runner.
4. `e6p_review.read_owned` returns only a Task/Mission label after rechecking the same enrolled session, live membership, exact owner UID, tenant, project and bound fence. This reauthorization happens in its own SQL transaction, not by trusting a previously cached preflight.
5. [`RuntimeE6POwnedPersistenceWriter`](../../orchestrator-service/src/main/java/io/aetheris/orchestrator/security/RuntimeE6POwnedPersistenceWriter.java) is an **unregistered, non-Spring** Java review adapter. It accepts only the existing independently RS256-verified sealed `VerifiedPrincipal`, checks read/write scope and calls the above functions with parameterized SQL through separate function-only PostgreSQL LOGIN accounts. It requires a fresh, writable READ COMMITTED transaction. No task service, mission service, public servlet or controller wires this candidate in.

## Mandatory actual Platform JWT + real PostgreSQL16 tests

[RuntimeE6PActualShapedOwnerWriterPg16IT](../../orchestrator-service/src/test/java/io/aetheris/orchestrator/security/RuntimeE6PActualShapedOwnerWriterPg16IT.java) uses two **actual original Platform-signed** tokens generated by the independently checked-out Platform E6K issuer, not mocked JWTs. All cases use the real disposable PostgreSQL 16 server:

1. Historical Task and Mission rows retain all NULL owner fields and cannot be fetched through the owner-gated function.
2. Platform-signed DEVELOPER creates new owned Task and Mission rows in their actual-shaped persistent tables, with immutable identity and fence, and reads both. API_CONSUMER cannot read those objects or write.
3. API_CONSUMER write, cross-tenant/project and wrong-fence attempts, and signed but unregistered JTI are denied without inserting a row.
4. Independently authenticated writer/reader SQL LOGIN accounts cannot directly SELECT, UPDATE, or invoke the opposite role's function.
5. Even a disposable test administrator cannot retroactively bind the historical records or change the owner UID of an existing owned Task or Mission.
6. Inactive workload fence denies creation and previous owned reads.
7. A concurrent uncommitted membership revocation holds the authority row lock; a create attempt fails closed on bounded SQL timeout rather than committing an unauthorized Task. After revocation commit, creation remains denied and the old owned resource becomes unreadable.

The existing Runtime 377 Java regression tests remain mandatory and the original Platform token-producing test still executes. All real Task/Mission product HTTP endpoints remain **404**; the global SSE boundary remains disabled.

## Remaining release gaps — S0-E6Q

- This is a disposable clone of the **relevant JPA schema shape**, not the live Task/Mission database. Actual production schema, existing migrations, constraints, indexes, object IDs and historical ownership cannot be assumed identical. Mission does **not** yet have JPA-owned columns. No real owner-authorized TaskService/MissionService creation, update, transition, attach or event path is enabled.
- SQL functions do not independently validate RSA signatures. Their caller must hold a separately authenticated function-only DB identity and use the original independent Runtime JWT verifier. Real issuance/DB access, Gateway workload identity, key custody, PKI, certificate expiry/rotation and production mTLS are not certified. Passing a tenant/project/fence ID as a caller parameter is only safe after a separately approved workload binding/authorization service establishes it.
- No tenant-scoped Task↔Mission **attachment**, TaskEventJournal, message, multi-owner access or event replay is certified. Runtime global SSE must remain disabled.
- Real migration needs explicit Flyway/Liquibase (or equivalent) adoption, ownerless-record retention/quarantine/backfill policy, immutable change review, staged backup/restore/rollback, per-resource permission invariants, no `ddl-auto=update` in production, performance and concurrency profiling, operator deployment approval and independent owner-PC/Stage45 attestations.
